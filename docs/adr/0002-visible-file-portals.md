# ADR-0002：用可见传送通道替代跨屏原生文件拖放

日期：2026-10-14。状态：已实现，双机原生拖放验收待完成。

## 背景与决策

用户在实际使用中发现跨屏拖拽未完成文件传输，并明确提出：两台电脑相邻边缘的中部各显示一个可见投放区，松手后发送文件，目的地统一为对方的下载目录。此决策更新报告 §10 / U01 / F24 的首版交互范围。

旧实现需要在切屏时读取系统拖拽剪贴板、用不可见窗口截住源拖拽、模拟按键结束源拖拽，再在远端以 NSFilePromiseProvider 重建拖拽。此次移除 `DragBridge.swift` 和 `agent/drag.rs`，文件发送不再依赖原生拖拽跨进程、跨电脑延续。低层平台模块里未被调用的拖拽辅助接口不参与新流程。

新流程以一次本机原生 drop 为边界：AppKit 接收本机文件 URL 后，Rust 后台提供内容，对方自动拉取并保存。光标在哪台电脑、使用哪台电脑的鼠标，都不影响文件传输的方向：方向由文件所在电脑决定。

## 用户行为与界面

- 左边电脑选择“对方在右侧”，投放区位于本机右边缘；右边电脑选择“对方在左侧”，投放区位于本机左边缘。
- 每台电脑一个 104 × 176 点的 NSPanel，居于对应方向最外侧显示器的垂直中心。尺寸是首轮交互初值，尚无真人拖放命中率测量。多个显示器同为最外侧时采用 NSScreen 列表的第一个。
- 面板不激活应用，在不同 Space / 全屏应用中请求显示。实际全屏兼容性需要双机现场测试。
- 连接且共享开启时显示；协议不支持或本机文件监听端口不可用时禁用投放。断开或暂停共享时隐藏。
- 投放区显示目标设备、松手提示、准备状态、传输数量和短暂结果。详细进度、取消、错误和下载目录入口在主窗口中。
- 接受文件 URL、文件夹和符号链接；拒绝普通文本、网页 URL 及无本地文件 URL 的 promise-only 拖拽。始终声明 copy，不删除源项目。
- 保留既有每方向 16 个未完成任务上限；一次投放 1–16 个顶层项目，文件夹整体算一项。批量容量不足时整批拒绝，不静默丢掉其中几项。当前每项一个接收 worker，上限仍为 16，尚未针对真实雷雳吞吐调优并发。
- 成功记录沿用 4 秒保留时间；失败和取消记录沿用 60 秒，可手动移除。已完成文件始终可从“打开下载目录”找到。

## 职责与调用链

```text
Finder / 本机应用的文件 URL
  → TransferPortal / PortalDropView（主线程，只完成原生 drop）
  → AppModel.sendFiles（后台 Task）
  → UniFFI Agent.send_files（检查顶层文件元数据）
  → Engine Command::SendFiles（检查连接、版本、共享状态，发送 offer）
  → Transfers.offer_files（创建待发送记录与一次性可领取项目）
  → 对方 Engine / Transfers.receive_offer（接收端自己提供 Downloads）
  → 独立 bulk TCP / osm-transfer（清单、分块、SHA-256、暂存、原子提交）
  → TransferReceipt（对方保存成功）
  → 发送端完成状态
```

`osm-core` 仍是 sans-IO。输入事件仍由 Rust 捕获、路由和注入，不通过 Swift 或 UniFFI。文件清单扫描、读写和网络接收在后台 worker 中完成，不在 AppKit 主线程或输入引擎线程读取内容。

接收目录由 Swift 的 `FileManager.urls(for: .downloadsDirectory, in: .userDomainMask)` 解析，构造 Agent 时传入。协议不携带接收端路径。Rust 在 join 路径前校验文件名是单个合法 macOS 路径组件，拒绝绝对路径、`..` 和带子路径的顶层名称。目标目录不存在时尝试创建；权限拒绝等错误作为传输失败显示，不回退到其他目录。

Info.plist 添加 `NSDownloadsFolderUsageDescription` 解释用途；它不会授予权限或替代系统选择。Apple 将该说明列为可选但推荐，是否弹窗取决于访问方式和现有授权。[Apple 文档](https://developer.apple.com/documentation/bundleresources/information-property-list/nsdownloadsfolderusagedescription)

## 防止切屏打断 drop

`Router` 在以下两条输入路径阻止边缘切换：

1. 本机物理鼠标：`LocalMove.left_down == true` 时不产生 Enter。
2. 远端控制本机：记录注入左键状态；按住左键时将坐标限制在本机显示器内，不产生 Leave。随后仍将松键注入本机，让 Finder / AppKit 完成 drop。

该规则覆盖整个边缘，因此快速拖动、主线程稍慢或未触发 draggingEntered 时也不会跨过去。其影响是所有左键拖动（包括选字、拖窗口）都要松手后才能切屏。没有按住左键时，原来的双向切屏行为保留。断线、紧急返回、暂停共享仍释放已注入的按键。

## 协议与完成语义

OSM/1 的 minor 从 1 升为 2，major 保持 1。

| 消息 | 方向 | 用途 |
|---|---|---|
| `PortalOffer`，控制消息 66 | 发送方 → 接收方 | 随机传输 ID、16 字节随机令牌、bulk 端口、项目名称/类型/大小；不含 input epoch |
| `PortalReject`，控制消息 67 | 接收方 → 发送方 | 共享暂停、容量不足、参数不合法等拒绝原因 |
| `FetchRequest` | 接收方 → 发送方 | 领取 offer 的一个项目；沿用 drag_id 字段编号，语义为 transfer_id |
| manifest/chunks/hash/`TransferDone` | 发送方 → 接收方 | 沿用既有内容传输与完整性校验 |
| `TransferReceipt`，bulk 消息 8 | 接收方 → 发送方 | 校验并原子提交完成后确认；空 error 表示成功 |

发送端必须读到成功 receipt 才结束为成功。内容写出但尚未收到 receipt 时显示“等待对方确认保存”。EOF、超时、无效响应和失败 receipt 均不能当成成功。接收端若已保存而确认丢失，双方可能分别显示接收成功与发送失败；重试前应检查 Downloads，避免创建额外副本。

每个已提供项目只能领取一次；同一个 receive offer 在最近 32 个 ID 内重放不会重复落盘。pending offer 60 秒无人领取时失败并失效。断开控制连接时撤销尚未领取的项目，已建立的 bulk 连接可以继续完成或自行失败。保留连接超时 3 秒、I/O 无进展超时 60 秒及 256 KiB 文件分块，不在此次修改中调参。

旧版仍可使用键鼠消息，但只有宣布 minor ≥ 2 的对端才会收到新 offer。收到旧 DragOffer 时明确回复 DragEnd(false)，不启动隐形窗口或代理拖拽；两台电脑均需升级才能使用通道。

## 复用的传输保证与边界

- SHA-256 校验每个文件，目录内 staging，校验后独占原子改名；不覆盖已有目标，同名自动加编号。
- 空文件、空目录、Unicode 名称、符号链接、源修改检测、磁盘余量检查继续由 osm-transfer 实现。
- 取消时关闭关联 socket 并置取消标记，流式操作清理临时目录；未开始的发送也可取消。
- 暂不支持断点续传、任意远端目标目录、跨屏连续拖动图标、剪贴板文件传输或 Windows。
- 保存成功表示已有实现的校验与原子提交成功，不新增掉电持久化保证。

## 已验证与待验证

已执行自动验证：

- 两个 Transfers 实例经真实 loopback TCP 互传文件和目录，双向复制、自动创建 Downloads、同名保留、源内容保留、重复 offer 不重复落盘。
- 发送端等待保存确认；拒绝确认或关闭连接会失败。
- 无效目录、非法文件名/令牌/端口、容量不足、未开始时取消、断连和超时。
- 物理鼠标和远端注入鼠标，在左右两个方向上按住拖动均不会切屏，松手后恢复正常切屏。
- Swift 真实 NSPasteboard 的多个文件 URL 解析，以及非文件内容拒绝；多显示器坐标和左右位置计算。
- osm-transfer 既有 24 项文件系统/传输测试（包括内容损坏、半途断开、取消及清单攻击）回归。

本次构建产物为 ARM64；本机没有可用 Developer ID 身份，因此打包脚本使用 ad-hoc 签名，`codesign --verify --strict` 通过。此产物仅作测试分发，不能据此确认升级后的 TCC 授权连续性，也没有经过公证。

双机现场验收应使用相同新版、Developer ID 签名的 `.app`；当前 ad-hoc 包可用于初步试用，但可能需重新授权，不能用 loopback 测试声称已完成权限相关验收：

| 场景 | 操作与通过标准 |
|---|---|
| 左 → 右 | 从左机 Finder 将小文件投到右边通道；右机 Downloads 出现文件，两边显示完成 |
| 右 → 左 | 使用右机物理鼠标反向重复；再用左机共享的鼠标控制右机重复，均保存到左机 Downloads |
| 双向位置 | 改左右配置或接外接显示器，投放区跟随正确外边缘，不落在显示器之间的空隙 |
| 取消拖拽 | 在通道外松手或按 Esc；不创建传输记录和远端文件 |
| 输入隔离 | 按住文件推到边界不切屏；松手发送后普通移动可切屏；正常键鼠和 Fn 组合键继续可用 |
| 批量与大目录 | Unicode 文件夹、空文件、多个文件及大目录；校验大小/哈希与源一致，同名不覆盖 |
| 权限拒绝 | 拒绝 Downloads 访问，显示失败，无错误的发送成功；授权后重新投放成功 |
| 全屏 / Spaces | 通道可见并接收 Finder 文件；切换空间时不会抢键盘焦点 |
| 中途取消 / 拔线 | 传输停止或报错，无可见半成品；鼠标恢复本机，重新连接后可再次投放 |
| 旧版本 | 一端旧版时新通道不接受投放，键鼠连接不被未知新消息打断 |
