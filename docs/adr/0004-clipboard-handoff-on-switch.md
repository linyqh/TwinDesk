# ADR-0004：切屏时交接剪贴板

日期：2026-10-16。状态：已实现，双机现场验收待完成。

## 背景与决策

用户反馈：在右边电脑 Cmd+C 后，到左边电脑 Cmd+V 粘贴不到对方的内容。此前剪贴板共享完全没有实现。

报告 §9.1 / F22 要求按需粘贴：复制时不覆盖其他电脑，用独立的“远程粘贴”热键触发传输，并且不得拦截 Cmd+V。用户选择改为切屏时交接，此决策更新 F22 的首版交互。

- 光标离开哪台 Mac（本机控制对方开始，或被控结束回到对方），就由这台 Mac 提供剪贴板。前提是连接后它的剪贴板有过变化，且自上次交接后又有新的复制。
- 对方取到内容后写入本机剪贴板，之后普通 Cmd+V 和菜单“粘贴”都可以直接使用。不拦截、不注入任何按键。
- 没有切屏就不会同步。连接前复制的内容不推送；从对方收到的内容不会在切回时回传。

## 协议

协议 minor 从 3 升为 4，major 保持 1。

| 消息 | 位置 | 用途 |
|---|---|---|
| `ClipboardOffer`，控制消息 68 | 被离开的 Mac → 另一台 | offer ID、16 字节随机令牌、bulk 端口，不含内容 |
| `ClipboardFetch`，bulk 消息 9 | 接收方 → 提供方 | 代替 `FetchRequest` 打开一条 bulk 连接 |
| `ClipboardFormat`，bulk 消息 10 | 提供方 → 接收方 | 每种格式的类型和字节数，随后是 `FileChunk`，最后是 `TransferDone` |

内容只走 bulk 连接，不在输入通道前排队。只向声明 minor ≥ 4 的对端发送 offer；旧版对端照常使用键鼠和文件通道。

## 格式与限制

- 传输 `public.utf8-plain-text`、`public.rtf`、`public.html`、`public.png`，以及 `public.tiff`（已有 PNG 时不再发送 TIFF）。按写入方的偏好顺序写成同一项。
- 文本类每种格式 16 MiB、图片 64 MiB（报告 §9.3 的 D 值，尚无内存实测）。超限的格式会被丢弃；全部超限时本次不交接。接收方也执行同样的上限。
- 带有 `org.nspasteboard.ConcealedType` / `TransientType`（密码管理器等）或 `public.file-url`（Finder 复制文件）的内容不离开本机。文件请用传送通道。
- 日志只记录交接成功与否，不记录内容（§7.2）。

## 一致性

- 每个 offer 只能领取一次，令牌按常数时间比较。读取前后比对 `changeCount`；用户在此期间又复制了新内容时返回 `SOURCE_CHANGED`，不发送混合内容。
- 接收方在开始拉取时记下本机 `changeCount`。如果写入前用户在本机又复制了，或者有更新的 offer 到达，或者连接已断开，就放弃本次写入，不覆盖用户的新内容。
- 拉取超时为 10 秒（D）；失败只记日志，不弹错误，本机剪贴板保持原样。
- 准备 offer 和读写剪贴板都在工作线程中进行，输入引擎线程不等待剪贴板服务。唯一的例外是连接建立时读取一次 `changeCount`。

## 已验证与待验证

自动验证：私有 NSPasteboard 往返；格式筛选、密码/文件排除和上限；多分块传输以及恶意或截断数据流；单次领取、伪造令牌、源内容变化；接收期间本机复制、被新 offer 取代、断线；两套 Transfers 通过真实 loopback TCP 双向交接，并验证不会回传。

需要两台 Mac 都更新到新版后做现场验收：

| 场景 | 预期 |
|---|---|
| 右机复制文字，鼠标移到左机，Cmd+V | 粘贴出右机文字 |
| 浏览器复制带格式文本 → 对方的“备忘录”或 Pages | 保留格式；只接受纯文本的应用得到纯文本 |
| 截图到剪贴板（Cmd+Ctrl+Shift+4）→ 对方粘贴 | 图片一致 |
| 切过去又切回，未再复制 | 两边剪贴板都不变 |
| 1Password 等复制密码后切屏 | 对方剪贴板不变 |
| Finder 复制文件后切屏 | 对方剪贴板不变 |
| 切过去后立即在对方本机复制 | 保留对方本机复制的内容 |
| 一端为旧版 | 键鼠和文件通道正常，不交接剪贴板 |
